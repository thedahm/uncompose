# Acceptance test: the vertical slice through installed wheels

This is the release gate for the Uncompose ecosystem (M6). It installs all
three packages — `uncompose`, `uncompose-project`, `uncompose-compare` — into a
clean environment and drives the vertical slice as a user types it, then reads
only what a user can read: exit codes, stdout, stderr, and the project
manifest.

It is the highest seam in the ecosystem. Nothing here imports any tool's
internals, looks inside a cache, or inspects a wheel's contents; the installed
commands are reached through `PATH` and nothing else.

## Running it

```sh
uv sync              # in this directory
uv run pytest
```

The default mode builds what it installs, so the gate is runnable before
anything is tagged: the extensions from git refs, the root package from this
checkout. That build needs `uv`, `git`, `cargo`, and `npm` on your `PATH`
(Node only because `uncompose-compare` embeds its frontend in the binary at
compile time). Without them the installed-artifact tests skip; set
`UNCOMPOSE_ACCEPTANCE_REQUIRE=1` — as CI does — to turn that skip into a
failure, because a gate that cannot run has not passed.

The `uv run pytest` command with no toolchain at all still runs the harness's
own unit tests (wheel sourcing, fixtures), which need neither network nor
compiler.

## Wheel sourcing

Where the three packages come from is the only thing that differs between a
pre-tag run and a post-release one; the test body is identical.

| Variable | Default | Meaning |
| --- | --- | --- |
| `UNCOMPOSE_ACCEPTANCE_MODE` | `build` | `build`: extensions from git refs, root from the checkout. `pypi`: all three from the index. |
| `UNCOMPOSE_ACCEPTANCE_CHECKOUT` | this repo | Root package source in `build` mode. |
| `UNCOMPOSE_ACCEPTANCE_PROJECT_URL` / `_COMPARE_URL` | the family repos | Clone source; point at a fork to gate one. |
| `UNCOMPOSE_ACCEPTANCE_PROJECT_REF` / `_COMPARE_REF` | `main` | Branch, tag, or commit sha. |
| `UNCOMPOSE_ACCEPTANCE_ROOT_VERSION` / `_PROJECT_VERSION` / `_COMPARE_VERSION` | unset | Pins each package in `pypi` mode; unset takes what the index serves. |
| `UNCOMPOSE_ACCEPTANCE_REQUIRE` | unset | Any value but `0`: never skip. |

So the pre-tag gate is the default, and verifying a published release is:

```sh
UNCOMPOSE_ACCEPTANCE_MODE=pypi \
UNCOMPOSE_ACCEPTANCE_ROOT_VERSION=0.1.0 \
UNCOMPOSE_ACCEPTANCE_PROJECT_VERSION=0.1.0 \
UNCOMPOSE_ACCEPTANCE_COMPARE_VERSION=0.1.0 \
UNCOMPOSE_ACCEPTANCE_REQUIRE=1 uv run pytest
```

## The separations are fake, and that is the point

The gate never runs a separation model, downloads weights, or needs a GPU: the
source recording is deterministic seeded noise and the two "separation runs"
are hand-built job folders, generated by the repo's own
[`demo/build_demo.py`](../demo/build_demo.py) so the gate and the demonstration
project cannot disagree about the shape of a finished job. What is genuinely
under test is everything downstream of that: the wheels install, both dispatch
forms reach both extensions, `import` lands a source asset, two derivations and
their stems in the manifest, and `verify` is green over the result. See
[ADR-0007](../docs/adr/0007-acceptance-test-installed-artifact-seam.md) for why
the gate stops there rather than driving a real `separate`.

Each run works in a temporary directory with its own `HOME` and XDG
directories, so it never reads or writes the machine's caches, state, or
projects.
