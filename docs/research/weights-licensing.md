# Weights Licensing for Music Source Separation Models

Date: 2026-07-31. Ticket: issue #3.

**TL;DR.** For nearly every leading open source-separation model, the *code* is permissively licensed (MIT/Apache) but the *weights* are either explicitly restricted, explicitly non-commercial, or (most commonly) carry no stated license at all. Demucs weights are explicitly *not* MIT ("provided only for scientific purposes" per the author). Open-Unmix umxl is CC-BY-NC-SA. Spleeter's weights license is an open, unanswered question. Community RoFormer checkpoints range from explicit MIT (Kim Mel-Band) to GPL-3.0 (anvuew) to no license at all (viperx, jarredou, most UVR-ecosystem models). Debian's ML policy would put essentially all of these outside main; Fedora treats weights as "content" and bars NC licenses. The industry norm, which Uncompose should follow, is download-on-first-run from the original host, never bundling, with per-model license disclosure and a user-responsibility posture for input audio.

---

## 1. Demucs / HTDemucs

- **Code license:** MIT. "Demucs is released under the MIT license as found in the LICENSE file." ([facebookresearch/demucs README](https://github.com/facebookresearch/demucs); same statement in the continuation fork [adefossez/demucs README](https://raw.githubusercontent.com/adefossez/demucs/main/README.md)).
- **Repo status:** facebookresearch/demucs "was archived by the owner on Jan 1, 2025. It is now read-only." README: "As I am no longer working at Meta, this repository is not maintained anymore. I've created a fork at github.com/adefossez/demucs." ([repo page](https://github.com/facebookresearch/demucs)).
- **Weights license:** **None granted.** The author (adefossez) stated verbatim, 2022-05-23: "The model weights are not covered by the MIT license, and are provided only for scientific purposes." ([issue #327 comment](https://github.com/facebookresearch/demucs/issues/327#issuecomment-1134828611), verified against the GitHub API). The README makes no license statement about the weights. This applies with no stated distinction across htdemucs, htdemucs_ft, htdemucs_6s, hdemucs_mmi, mdx, mdx_extra, mdx_extra_q.
- **Training data:** htdemucs family and hdemucs_mmi: "trained on the MUSDB HQ dataset + an extra training dataset of 800 songs" (internal, unreleased). mdx: "trained only on MusDB HQ". mdx_extra: "trained with extra training data (including MusDB test set)". ([adefossez/demucs README](https://raw.githubusercontent.com/adefossez/demucs/main/README.md)). MUSDB18 itself "can only be used for academic purposes" ([sigsep MUSDB18 page](https://sigsep.github.io/datasets/musdb.html)), which taints even the MusDB-only mdx weights independent of Meta's terms. (A community comment in issue #327 makes the same MusDB argument; that comment is not authoritative.)
- **Hosting:** downloaded at first use from `https://dl.fbaipublicfiles.com/demucs/` (constant `ROOT_URL` in [demucs/pretrained.py](https://raw.githubusercontent.com/adefossez/demucs/main/demucs/pretrained.py)); file manifests in [demucs/remote/files.txt](https://raw.githubusercontent.com/adefossez/demucs/main/demucs/remote/files.txt) (dirs `mdx_final/`, `hybrid_transformer/`).
- **Redistribution:** no grant, so mirroring is legally unauthorized. Notably, a 2024 follow-up in issue #327 asking whether Intel's Hugging Face mirror (labeled MIT) and Linux-distro packaging are permitted went unanswered ([issue #327](https://github.com/facebookresearch/demucs/issues/327)). Widespread mirrors (TRvlvr model_repo, various HF repos) exist without any documented permission.

## 2. BS-RoFormer / Mel-Band RoFormer (community checkpoints)

- **Original:** ByteDance paper; no official ByteDance weight release found in any repo or HF org I checked (UNVERIFIED as a negative, but ZFTurbo's model list contains no ByteDance-hosted checkpoint).
- **Code:** [lucidrains/BS-RoFormer](https://github.com/lucidrains/BS-RoFormer) is MIT ([LICENSE](https://raw.githubusercontent.com/lucidrains/BS-RoFormer/main/LICENSE)). [ZFTurbo/Music-Source-Separation-Training](https://github.com/ZFTurbo/Music-Source-Separation-Training) is MIT ([LICENSE](https://raw.githubusercontent.com/ZFTurbo/Music-Source-Separation-Training/main/LICENSE)); its README credits lucidrains "for recreating the RoFormer models based on papers."
- **Checkpoints and their licenses** (per [docs/pretrained_models.md](https://github.com/ZFTurbo/Music-Source-Separation-Training/blob/main/docs/pretrained_models.md)):
  - The pretrained-models doc lists checkpoints by ZFTurbo, viperx, KimberleyJSN, aufr33, jarredou, SUC-DriverOld (Sucial), JusperLee, starrytong and others, hosted across GitHub releases (ZFTurbo repo, TRvlvr/model_repo, jarredou) and Hugging Face (KimberleyJSN, anvuew, JusperLee, Sucial). **The document contains no license statements or usage restrictions for any checkpoint.**
  - Kim Mel-Band RoFormer vocal model: HF repo [KimberleyJSN/melbandroformer](https://huggingface.co/KimberleyJSN/melbandroformer) carries an **MIT** license tag; the model card is otherwise empty (no training-data disclosure).
  - anvuew dereverb Mel-Band RoFormer: HF repo [anvuew/dereverb_mel_band_roformer](https://huggingface.co/anvuew/dereverb_mel_band_roformer) is tagged **GPL-3.0** (copyleft weights, commercial use OK).
  - viperx BS/Mel-Band RoFormer checkpoints: hosted in [TRvlvr/model_repo releases](https://github.com/TRvlvr/model_repo/releases) (the UVR download-center mirror). **No license file or statement found** for these release assets; default is all-rights-reserved. UNVERIFIED beyond absence in the ZFTurbo doc; I did not find any per-asset license page.
  - jarredou models (e.g. DrumSep MDX23C): GitHub releases under jarredou's account, no license statement found (UNVERIFIED per-release).
  - Checkpoints attached to ZFTurbo's own repo releases: arguably fall under the repo's MIT license, but this is an inference; there is no explicit statement covering release assets.
- **Redistribution:** only the explicitly licensed ones (Kim MIT, anvuew GPL-3.0) clearly permit it. Everything else is unlicensed-by-default. Also note the training-data question: many community vocal models are trained on private or MUSDB-derived datasets that are themselves non-commercial/academic, and trainers rarely disclose datasets.

## 3. MDX-Net (KUIELab) and UVR

- **KUIELab code:** [kuielab/mdx-net](https://github.com/kuielab/mdx-net) is MIT (repo sidebar). No weight-license statements found in its README.
- **UVR code:** MIT. README License section verbatim: "The **Ultimate Vocal Remover GUI** code is MIT-licensed. **Please Note:** For all third-party application developers who wish to use our models, please honor the MIT license by providing credit to UVR and its developers." A LICENSE file exists in the repo root. ([Anjok07/ultimatevocalremovergui](https://github.com/Anjok07/ultimatevocalremovergui)).
- **UVR models:** README: "UVR's core developers trained all of the models provided in this package (except for the Demucs v3 and v4 4-stem models)." The "honor the MIT license" sentence is the closest thing to a weights grant; it implies the models are usable (incl. commercially) with credit, but it is not a formal license text attached to the model files. A 2026 request for explicit commercial-use clarification ([issue #2185](https://github.com/Anjok07/ultimatevocalremovergui/issues/2185)) has no maintainer reply. **UNVERIFIED:** the often-repeated claim that "UVR models are free for commercial use except certain models trained on non-commercial data" — I could not find that wording in the current README or any primary UVR source; the only exception the README states is the Demucs v3/v4 provenance.
- **Hosting:** UVR's download center infrastructure lives in [TRvlvr/model_repo releases](https://github.com/TRvlvr/model_repo/releases) (`all_public_uvr_models` tag) with model metadata JSON in [TRvlvr/application_data](https://github.com/TRvlvr/application_data) (verified via python-audio-separator's source, which consumes exactly these endpoints). A separate "VIP" model set is fetched from `https://github.com/Anjok0109/ai_magic/releases/download/v5` (same source); its terms are nowhere stated (UNVERIFIED).
- The MDX-Net ONNX files distributed by UVR (Kim Vocal 1/2, Inst HQ series, etc.) carry no per-file license; they inherit only the informal README statement above.

## 4. Open-Unmix (sigsep/open-unmix-pytorch)

- **Code:** MIT ([README](https://raw.githubusercontent.com/sigsep/open-unmix-pytorch/master/README.md)).
- **umx** (MUSDB18): Zenodo record 3370486, license id `mit-license` ([Zenodo API](https://zenodo.org/api/records/3370486)).
- **umxhq** (MUSDB18-HQ): Zenodo record 3370489, license id `mit-license` ([Zenodo API](https://zenodo.org/api/records/3370489)). **Correction to a common belief:** umxhq is *not* CC-BY-NC-SA per its Zenodo record; it is MIT. (Whether an MIT grant on MUSDB-trained weights is effective given MUSDB's academic-only terms is a separate, unresolved question.)
- **umxl** (extra private data, the current default model): Zenodo record 5069601, **CC-BY-NC-SA 4.0**. README verbatim: "Note, that the weights are only licensed for non-commercial use (CC BY-NC-SA 4.0)." ([Zenodo](https://zenodo.org/records/5069601), [README](https://raw.githubusercontent.com/sigsep/open-unmix-pytorch/master/README.md)).
- **Hosting:** Zenodo (DOI-stable). Redistribution: umx/umxhq freely (MIT); umxl only non-commercially with attribution and share-alike.

## 5. Spleeter (deezer/spleeter)

- **Code:** MIT. "The code of **Spleeter** is MIT-licensed." ([README](https://raw.githubusercontent.com/deezer/spleeter/master/README.md), [LICENSE](https://github.com/deezer/spleeter/blob/master/LICENSE)).
- **Weights:** **no explicit license statement anywhere in the repo.** A direct question, "[Discussion] license for model weights" ([issue #898](https://github.com/deezer/spleeter/issues/898), opened 2024-04-26), notes the README only licenses the code; it remains open with no Deezer reply. Treat the weights as unlicensed-by-default.
- **Hosting:** downloaded at first use from Deezer's own GitHub releases: `DEFAULT_HOST = "https://github.com"`, repo `deezer/spleeter`, `RELEASE_PATH = "releases/download"`, `LATEST_RELEASE = "v1.4.0"` ([spleeter/model/provider/github.py](https://raw.githubusercontent.com/deezer/spleeter/master/spleeter/model/provider/github.py)).
- **Copyright disclaimer (verbatim):** "If you plan to use **Spleeter** on copyrighted material, make sure you get proper authorization from right owners beforehand." ([README](https://raw.githubusercontent.com/deezer/spleeter/master/README.md)).
- **Maintenance:** the repo is not archived and the README carries no deprecation banner, but the last model release is still v1.4.0-era and issue responses have stopped (issue #898 unanswered for 2+ years). "Effectively unmaintained" is fair but the repo itself makes no such statement (UNVERIFIED as a formal status).

## 6. Other current leaders (2025-2026)

- **SCNet** ([starrytong/SCNet](https://github.com/starrytong/SCNet)): code MIT; checkpoints (MUSDB-trained, plus a large version) linked via Google Drive in the README with **no stated weight license**. ZFTurbo also hosts SCNet Large/XL checkpoints in his repo releases (same unlicensed-by-default status).
- **Apollo** (audio restoration, [JusperLee/Apollo](https://github.com/JusperLee/Apollo)): repo badged **CC BY-SA 4.0** (share-alike, commercial OK); weights on Hugging Face (JusperLee). Weight files' own license tag not separately verified (UNVERIFIED).
- **Bandit-v2** (cinematic separation, [kwatcharasupat/bandit-v2](https://github.com/kwatcharasupat/bandit-v2)): code **Apache-2.0**; weights on Zenodo record 12701995 under **CC-BY-SA 4.0** ([Zenodo API](https://zenodo.org/api/records/12701995)). README adds a voluntary (non-binding) request that commercial beneficiaries donate to music nonprofits.
- **MVSep models:** mvsep.com is ZFTurbo's service; his public checkpoints are in the repo releases above. The claim that some MVSep-trained models are site-exclusive or restricted could **not be verified in any primary document** — [docs/pretrained_models.md](https://github.com/ZFTurbo/Music-Source-Separation-Training/blob/main/docs/pretrained_models.md) contains no exclusivity or restriction language. - **Moises:** no open weight releases found. Their [MoisesDB dataset repo](https://github.com/moises-ai/moises-db) states: "MoisesDB is distributed under the Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International License (CC BY-NC-SA 4.0)" — so anything trained on MoisesDB inherits an NC taint argument.

- **python-audio-separator** ([nomadkaraoke/python-audio-separator](https://github.com/nomadkaraoke/python-audio-separator)): code MIT ([README](https://raw.githubusercontent.com/nomadkaraoke/python-audio-separator/main/README.md)). ## 7. Acquisition patterns

All three major tools use **download-on-first-run, nothing bundled**:

- **demucs:** fetches from Meta's CDN `https://dl.fbaipublicfiles.com/demucs/` per manifests in `demucs/remote/` ([pretrained.py](https://raw.githubusercontent.com/adefossez/demucs/main/demucs/pretrained.py)).
- **Spleeter:** fetches `.tar.gz` model archives from its own GitHub releases (`deezer/spleeter`, release v1.4.0) ([provider/github.py](https://raw.githubusercontent.com/deezer/spleeter/master/spleeter/model/provider/github.py)).
- **UVR / python-audio-separator:** fetch from the TRvlvr mirror infrastructure. Verified in [audio-separator source](https://raw.githubusercontent.com/nomadkaraoke/python-audio-separator/main/audio_separator/separator/separator.py): public models from `https://github.com/TRvlvr/model_repo/releases/download/all_public_uvr_models`, "VIP" models from `https://github.com/Anjok0109/ai_magic/releases/download/v5`, model metadata from `https://raw.githubusercontent.com/TRvlvr/application_data/...` (download_checks.json, model_data_new.json), its own configs from `https://github.com/nomadkaraoke/python-audio-separator/releases/download/model-configs`, and Demucs weights directly from `https://dl.fbaipublicfiles.com/demucs/hybrid_transformer/`.
- **Re-hosting reality check:** mirroring is ubiquitous (TRvlvr mirrors everything incl. Demucs; Intel published an MIT-labeled Demucs mirror on HF) but for Demucs the author explicitly said the weights are not MIT, and the direct question about mirrors/distro packaging in [issue #327](https://github.com/facebookresearch/demucs/issues/327) was never answered. Most mirrors therefore rest on tolerated-infringement, not permission.

## 8. Linux distro packaging implications

- **Debian:** the Deep Learning Team's [ML-Policy](https://salsa.debian.org/deeplearning-team/ml-policy) classifies models as **Free Model** (FOSS-licensed model + "trained from explicitly FOSS-licensed & DFSG-compliant datasets... and the dataset is publicly available" + complete training code), **ToxicCandy Model** (FOSS-licensed model but trained on "unknown, private, or non-free datasets"), or **NonFree Model**. Only Free Models (with reproducibility) can enter main. Consequence: *every* model in this document is at best ToxicCandy (MUSDB is academic-only; htdemucs/umxl/UVR training sets are private), so none is main-eligible. Download-at-runtime by a packaged tool is the standard workaround (the downloader is free; the weights never enter the archive).
- **Fedora:** per the 2024 Fedora legal-list thread ([question](https://www.mail-archive.com/legal@lists.fedoraproject.org/msg03591.html), [Fontana reply](https://www.mail-archive.com/legal@lists.fedoraproject.org/msg03592.html)), pre-trained weights are treated as **"content"** ("not clearly code, documentation, fonts or firmware"); content with an allowed license "can be included in Fedora packages." Fontana explicitly declined to require free training data, distinguishing Fedora from OSI's Open Source AI definition. But **non-commercial licenses are not allowed content**: the thread notes weights "distributed as CC-BY-NC-4.0... would not be acceptable for use in a Fedora package" ([msg03629](https://www.mail-archive.com/legal@lists.fedoraproject.org/msg03629.html); background: [LWN, "Questions about machine-learning models for Fedora"](https://lwn.net/Articles/964739/)). Unlicensed weights (Demucs, Spleeter, most UVR models) fail both distros trivially.

## 9. Implications for Uncompose's license choice

- **Code license is a free choice.** Weights are data loaded at runtime, not linked code; neither MIT nor GPL for Uncompose's code creates any interaction with weight licenses (GPL's copyleft reaches derivative *software*, not independently distributed data files the user downloads). Pick MIT/Apache/GPL on their own merits.
- **Never bundle weights in the release artifact or repo.** Concretely: Demucs (no grant, "scientific purposes only"), umxl (CC-BY-NC-SA), Spleeter (no grant), all TRvlvr/UVR-hosted checkpoints and viperx/jarredou models (no explicit grant). Bundling any of these is unauthorized redistribution; bundling NC weights also poisons commercial use of Uncompose.
- **Download-on-first-run from the original host** (dl.fbaipublicfiles.com, Zenodo, HF, upstream GitHub releases), exactly like demucs/Spleeter/UVR do. Do not stand up a Hugging Face mirror unless the specific checkpoint has an explicit permissive license (Kim Mel-Band MIT, Bandit-v2 CC-BY-SA, umx/umxhq MIT, anvuew GPL-3.0).
- **Surface license status per model** in the UI/docs (license name, "no license / research only" where applicable) so commercial users of Uncompose can make informed choices; Uncompose itself, as a tool, is not the entity "using" the weights, the user is, but distributing restricted weights would be.
- Caveat to document: copyrightability of weights is legally unsettled, and trainer-asserted licenses (e.g. MIT on MUSDB-trained checkpoints) may exceed what the trainer can actually grant given dataset terms. Uncompose should relay upstream claims, not certify them.

## 10. Copyright posture toward user-supplied audio

- **Spleeter** (verbatim): "If you plan to use **Spleeter** on copyrighted material, make sure you get proper authorization from right owners beforehand." ([README](https://raw.githubusercontent.com/deezer/spleeter/master/README.md)).
- **UVR:** no input-audio copyright disclaimer found in the README ([repo](https://github.com/Anjok07/ultimatevocalremovergui)).
- **Demucs:** no such disclaimer in the README.
- **Moises** (hosted-service contrast): their ToS reportedly places responsibility for uploaded content rights on the user; not verified against the current terms text (UNVERIFIED).
- **Recommended posture for Uncompose:** a Spleeter-style disclaimer. State that (a) the user is solely responsible for having rights to any input audio, (b) separated stems are derivative of the input sound recording, so rights in the outputs are governed by rights in the input; Uncompose grants no rights in outputs, (c) the tool runs locally and never receives the audio, which keeps Uncompose out of the distribution chain entirely. This matches the strongest precedent (Deezer, a music company, shipping Spleeter under MIT with only a use-authorization notice).
