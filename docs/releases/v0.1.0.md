# Uncompose v0.1.0

First release. Uncompose is a local-first, open-source music source separation CLI
for Linux: you give it a song (WAV/MP3), it gives you a folder of stems next to the
input, separated on your own hardware. No accounts, no uploads, no telemetry.

## What it does

- `uncompose separate song.mp3` — a `6-stem` default preset (vocals, drums, bass,
  guitar, keys, other; a Mel-Band RoFormer vocal pass, then htdemucs_6s) and a
  `2-stem` preset (vocals/instrumental; GPU-required).
- Installs from PyPI with uv (`uvx uncompose`); the Python ML engine environment is
  built automatically on first run, and model weights (≈900 MB) download
  automatically with hash verification and each model's license status shown.
- Every job folder is self-describing: stems plus a `job.json` recording input hash,
  models, parameters, device, engine version, and timings — written last, so its
  presence marks a complete job. Reruns collision-suffix, never overwrite.
- `play` auditions a stem via mpv/ffplay; `open` opens the job folder;
  `models list/fetch/remove` manage the weight cache.
- CUDA is the primary target with CPU fallback. Machine of record: Ubuntu Studio
  26.04, RTX 4060 Ti — full songs separate there in 1 to 5 minutes. CPU output is
  identical, just slow (tens of minutes).

## What it does not do

- No claim to state-of-the-art separation quality: the models are current open
  checkpoints chosen by a listening A/B against one commercial reference, nothing
  more. Model licenses are relayed, not certified — htdemucs_6s weights are
  research-only; check them against your use.
- `keys.wav` is piano-trained: synths and organs usually land in `other.wav`.
- Linux only. macOS and Windows are untested; reports welcome.
- Stems currently inherit the input's bit depth (16-bit from MP3, 24-bit from
  24-bit WAV) rather than the intended 32-bit float; audio-separator exposes no
  output-depth control. Planned fix.
- No batch processing, no web UI, no daemon, no container/AUR packages yet.

Full decision history lives in `docs/adr/` and the issue tracker.
