# Uncompose v0.2.0

Uncompose becomes a family. This release adds the external-command dispatch that
turns the `uncompose` CLI into the front door for its extensions — released
separately as [`uncompose-project`](https://pypi.org/project/uncompose-project/) and
[`uncompose-compare`](https://pypi.org/project/uncompose-compare/), both cutting
their own v0.1.0 alongside this release — and the project-aware separation that
ties them together. Separation itself is unchanged from v0.1.0.

## What's new

- **External-command dispatch** (ADR-0005): `uncompose <token> …` execs
  `uncompose-<token>` from `PATH`, so `uncompose project init` and
  `uncompose compare a.wav b.wav` reach the installed extensions. A token that
  matches nothing gets an install hint and a did-you-mean; `uncompose --help`
  lists the extensions it actually found.
- **`separate --project`**: separation runs pre-flight against a project manifest
  and chain their results into it — the job's stems land as registered assets and
  a derivation, so `uncompose project show` and `verify` see them without a manual
  import step.
- **Root `--version`/`-V`** printing `uncompose X.Y.Z`, the anchor the family's
  version reporting hangs off.
- **Extension author guide** and a worked example extension, for anyone who wants
  an `uncompose-<something>` of their own.
- **End-to-end walkthrough** (`docs/walkthrough.md`) and a reproducible demo
  project driving the whole slice: separate twice, inspect the derivation graph,
  compare blind, and see the evaluation land back in the manifest.

## Fixes

- `-o` can no longer escape the output root via `..` in a not-yet-created
  directory.

## What it does not do

The v0.1.0 limitations still stand: no state-of-the-art claim, `keys.wav` is
piano-trained, Linux only, stems inherit the input bit depth, no batch mode. The
engine is unchanged; `uncompose-engine` 0.2.0 is a version-number companion to the
CLI wheel with no behavioral change.

Full decision history lives in `docs/adr/` and the issue tracker.
